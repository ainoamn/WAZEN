## 1) فتح المشروع على جهاز جديد

المتطلبات: **Node.js 22.x** (مثبّت في `package.json` → `engines.node`. Vercel يستخدم 22 وليس 24).

```powershell
git clone https://github.com/ainoamn/WAZEN.git
cd WAZEN
git checkout main
git pull --ff-only origin main
npm install
copy .env.example .env.local
# املأ الأسرار من Vercel / Neon — لا تضعها في Git
npm run setup:local
npm run dev
```

قائمة المتغيرات في `.env.example`. للإنتاج راجع [NEON-SETUP.md](./NEON-SETUP.md) و [PRODUCTION-DEPLOYMENT.md](./PRODUCTION-DEPLOYMENT.md).

الجداول والأعمدة الجديدة تُنشأ عند أول `GET /api/dashboard` عبر `ensureSchema` في `db/runtime.ts` (لا حاجة لهجرة يدوية لمعظم أعمدة الفترات).

اختبارات:

```powershell
npm run test:backend
npm run build
```

النشر: الدفع إلى `main` يشغّل Vercel تلقائياً.

## 3) ماذا اكتمل حتى 14 أغسطس 2026

### صفحة الأعضاء (ملف شخص)

- الجدول يعرض أشخاصاً موحّدين عبر الهاتف / البريد / الاسم (`personIdentityKey`).
- أعمدة: الاسم، **نشط / غير نشط**، عدد الجمعيات، تقييم الانضباط، عليه، المستلم.
- الضغط على الاسم يفتح `MemberPersonProfile`: بيانات الاتصال، درجة الانضباط، المجاميع، الجمعيات المرتبطة.
- الضغط على جمعية يعرض حالة الدفع والأقساط داخلها.

ملفات: `app/wazen-dashboard.tsx` (`MembersView`)، `components/members/association-members.tsx`.

### الفترة المحاسبية

- إغلاق الفترة: `closeAccountingPeriod` — يقفّل التعديل على الحركات داخل نطاق التاريخ (`status=closed`).
- **إعادة فتح:** زر بجانب الفترة المغلقة → `reopenAccountingPeriod` → `status=reopened`. التعديل مسموح ثم يُغلق مرة أخرى بزر إغلاق الفترة.
- **طباعة:** زر بجانب الفترة المغلقة/المعاد فتحها → كشف دخل، مصروفات، مصروفات إضافية، أعضاء (`reportType: period` في `lib/reports.ts`).
- **سجل التدقيق الظاهر:** جدول `period_ledger_events` — من أغلق، من أعاد الفتح، وكل إضافة/تعديل/إلغاء حركة مرتبطة. يظهر تحت بطاقة الفترة في الواجهة.
- الأعمدة على `accounting_periods`: `closed_by`, `reopened_at`, `reopened_by`, `reopen_count`.
- المنطق: `lib/accounting-periods.ts` (`coveringPeriod`, `isPeriodLocked`).

### مصروفات المجموعة والتسويات

- تعديل المصروف وإعادة التقسيم بالتساوي بمن فيهم الأعضاء الجدد.
- عمود «له» للدافع = ما دفعه عن الآخرين، وليس حصته مضاعفة.
- التسوية يمكن أن ترفع `addon_minor` (مبالغ إضافية) مع `allocation: extra`.

### محافظ / جمعيات

- `spaces.starts_at` تاريخ بداية المحفظة.
- استنساخ فترة جديدة: `addWallet` مع `cloneFromSpaceId` + اختيار أعضاء من `saved_contacts`.
- صفحة الجمعيات تعرض `society` / `group` والأسماء المشابهة لجمعية.

### أخرى حديثة

- قائمة حساب تعمل (خروج + إعدادات).
- هواتف عمانية 7 أرقام مقبولة.
- المحاسب الذكي + فواتير الأشهر المتبقية عند السداد.
- هدف العضو = القسط الشهري × عدد الأشهر (`due_minor`).

## 5) تحقق يدوي بعد النشر

1. جمعية → أغلق الفترة → اختفِ أزرار تعديل/حذف الحركات داخل الفترة، واظهر **طباعة** و**إعادة فتح**.
2. إعادة فتح → يظهر «مفتوحة للتعديل» واسم من فتح → عدّل حركة → تظهر في **سجل الفتح والتعديلات**.
3. أغلق مجدداً → القفل يعود.
4. الأعضاء → نشط/غير نشط → اضغط الاسم → جمعية → أقساط.
5. طباعة الفترة: دخل، مصروف، إضافي.

## 6) أعطال بناء حديثة (لا تكررها)

عند إضافة `assertPeriodWritable` لا تحذف بداية ternary (`const linkedTxn = expense.transaction_id ? ...`).  
لا تحذف استيرادات: `isLikelyPhone` / `toWhatsAppNumber` من `lib/phone`، و`buildReportHtml` / `openReportPreview` من `lib/reports`.  
عند تعديل مصروف جماعي أبقِ `let amountMinor = Number(expense.amount_minor)` قبل إعادة التعيين.

Vercel: TypeScript يفشل البناء حتى لو نجح Compile. راقب `tsc` في سجل النشر.
