## أين وقفنا (نقطة الاستكمال)

اكتمل بناء **نظام إدارة الباقات وبوابات الدفع** وربطه بالمستخدمين والصلاحيات، مع تحسينات موبايل/أداء، ونُشر على Vercel.

### مكتمل

1. **بوابات الدفع (Admin)** — `/admin/gateways`  
   - كتالوج محلي/إقليمي/عالمي (ثواني، عمان نت، بنك مسقط، تاب، ميسّر، سترايب، باي بال، تحويل يدوي، …)  
   - تفعيل / وضع تجريبي / ربط بالباقات  
   - جداول: `payment_gateways`, `plan_payment_gateways`

2. **الباقات (Admin)** — `/admin/plans`  
   - تعديل الأسعار، الحدود، `features_json`، ربط البوابات  
   - لم تعد تشير قائمة الإدارة إلى `/pricing` فقط

3. **تحكم اشتراك المستخدم** — `/admin/users/[id]`  
   - ترقية / إيقاف / استئناف  
   - خصم خاص (`discount_percent`, `discount_fixed_minor`, `discount_label`)  
   - تاريخ بداية/نهاية الفترة، الفواتير، المعاملات

4. **الصلاحيات عند الاشتراك**  
   - نوع المحفظة حسب `features_json` في `addWallet`  
   - حد المحافظ والأعضاء  
   - المستندات المتقدمة تتطلب ميزة `documents`

5. **موبايل + أداء**  
   - دفتر الصفحة الرئيسية أصغر على الهاتف بدون قصّ المبالغ  
   - بطاقات/أيقونات لوحة المستخدم والإدارة متسقة على الشاشات الضيقة  
   - إيقاف reseeding الثقيل في كل طلب API + كاش عميل لصفحات الإدارة

### غير مكتمل / التالي المقترح

| أولوية | المهمة | ملاحظات |
|--------|--------|---------|
| P1 | ربط مفاتيح API الحقيقية لكل بوابة (Thawani/Stripe/…) | الواجهة الإدارية جاهزة؛ الأسرار عبر env مشفّرة |
| P1 | Checkout فعلي عند `selectPlan` عبر البوابة المختارة | حالياً فاتورة + `pending_payment` / يدوي |
| P2 | مزامنة `features_json` للباقات الموجودة مرة واحدة بسكربت ترحيل | أُزيل التحديث القسري في كل طلب لأسباب أداء |
| P2 | تقليل حمولة `scopedAdminData` (لا تجلب كل الجداول لكل scope) | يؤثر على سرعة `/admin` |
| P2 | Staging مطابق للإنتاج قبل تغييرات DB كبيرة | انظر backlog الحالي |
| P3 | دعوات فريق الإدارة + مصفوفة صلاحيات كاملة | `/admin/staff` عرض فقط حالياً |

## ملفات أساسية أُضيفت/تغيّرت

| مسار | دور |
|------|-----|
| `services/admin/billing-service.ts` | كتالوج البوابات، CRUD باقات/بوابات، entitlements، سجل فوترة المستخدم |
| `app/admin/gateways/page.tsx` + `billing-admin-client.tsx` | واجهة بوابات الدفع |
| `app/admin/plans/page.tsx` | واجهة الباقات |
| `app/admin/admin-detail-client.tsx` | لوحة تحكم اشتراك المستخدم |
| `app/api/platform/route.ts` | actions: `updateGateway`, `upsertPlan`, `adminUpdateSubscription` + scopes |
| `app/api/dashboard/route.ts` | فرض صلاحيات الباقة عند إنشاء محفظة/أعضاء |
| `db/runtime.ts` | جداول البوابات + أعمدة اشتراك إدارية |
| `app/page.tsx` + `app/commercial.css` | دفتر البطل (hero ledger) + موبايل |
| `lib/app-origin.ts` | أصل التطبيق الآمن (تسجيل/تحقق) |

## تشغيل من الجهاز الآخر بدون تعارض

```bash
git clone https://github.com/ainoamn/WAZEN.git
cd WAZEN
git checkout main
git pull origin main
npm ci
# انسخ .env.local من الجهاز السابق أو من Vercel (لا ترفع الأسرار إلى Git)
npm run dev
```

### قواعد لتجنب التعارض

1. ابدأ دائماً بـ `git pull --ff-only origin main`  
2. لا تعدّل نفس الملفات على جهازين دون سحب/دفع متسلسل  
3. لا ترفع `.env` / كلمات مرور Neon أو مفاتيح الدفع  
4. إن ظهر تعارض: حلّه محلياً ثم commit جديد — لا تستخدم `--force` على `main`  
5. النشر: `npx vercel --prod --yes` بعد الدفع إلى `main` إن لزم

### متغيرات بيئة مهمة (Vercel / محلي)

- `DATABASE_URL` أو `NEON_DATABASE_URL`  
- `WAZEN_ADMIN_EMAILS` / مسار bootstrap للمدير  
- `WAZEN_DEMO_MODE=0` في الإنتاج  
- مفاتيح البريد إن وُجدت للتحقق
